# RosterCopiilot Demo 使用說明

這個 demo 展示的流程是：

```text
系統內置固定分工基礎
+ 上載 HC 時間表
+ 上載護送總表
+ 輸入本週臨時變更
-> 自動生成照顧員工作分工表格式 Excel
```

## 需要準備的檔案

使用者需要上載兩個 Excel：

| 檔案 | 用途 |
| --- | --- |
| `2026_HC 時間表(HKU).xlsx` | 提供目標週內的家居清潔、個人照顧、沖涼及其他服務需求 |
| `護送個案總表(2026)(HKU).xlsx` | 提供目標週內的護送/陪診需求、目的地、時間、科目及備註 |

系統內置一個固定基礎：

| 檔案 | 用途 |
| --- | --- |
| `照顧員工作分工表2026(HKU).xlsx` | 作為固定排班基礎與輸出模板，不需要每次上載 |

## 啟動方式

先啟動後端：

```bash
.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

再啟動前端：

```bash
python3 -m http.server 3000 --directory frontend
```

然後開啟：

```text
http://127.0.0.1:3000/
```

如果後端不是跑在 `http://localhost:8000`，可以在瀏覽器 Console 設定：

```javascript
localStorage.setItem("rc_api_base", "http://127.0.0.1:8000")
```

## Demo 操作步驟

1. 在「上載 HC 時間表」選擇 HC Excel。
2. 在「上載護送總表」選擇護送 Excel。
3. 選擇目標週星期一（選了其他日子會自動對齊至該週星期一）。
4. 如有臨時變更，選擇變更類型並填入同工/長者/目的地等資料，按「加入變更」；可加入多項變更後一次生成。沒有變更就直接生成。
5. 按「生成排班表」。生成後系統會自動保存目前工作，刷新頁面會自動恢復；也可在「工作狀態與存檔」把目前版本轉為不可變的固態存檔，或從存檔建立可編輯副本。
6. 檢查右側的發放狀態、解析摘要、臨時變更影響及審核項目；審核項目按分類顯示任務、涉及同工/長者、日期時段及原因。
7. 在「審核項目」填寫審核人；按情況批准、修改或強制略過（Hard-bypass）。修改／強制略過必須填備註；涉及硬規則的修改還要填覆核說明，且版本仍會保持「不可發放」。強制略過表示主管接受風險：保留目前安排，或停止該任務於本週執行。
8. 每次操作後，頁面會使用服務器返回的新版本、總數及發放狀態重新顯示；需要時可按「重新驗證」。提交審核後按鈕會顯示「處理中…」並暫時鎖定，請等候完成；若同一排班已在別處被改動，系統會提示並自動重新載入最新版本。不要用人手刪除資料缺口項目來取得綠色狀態。
9. 按「下載審核草稿」取得並行審核 Excel。若匯出前檢查發現硬性規則或落格失敗，系統會停止下載，避免改寫主表。
10. 只有服務器顯示「可發放」時，填寫正式版發佈人並按「發佈正式版」。成功後才可按「下載正式版」。發佈不會自動把檔案傳給同工或長者。

## 輸出檔案

審核階段下載的檔案名稱是：

```text
照顧員工作分工表_審核草稿.xlsx
```

只有另行執行 ready-only 發佈後，才會有：

```text
照顧員工作分工表_正式版.xlsx
```

正式版記錄會綁定當時的版本、內容 hash、發佈人、時間及檔案
SHA-256；任何後續排班版本都要重新審核及發佈。

工作簿內容：

| 工作表 | 內容 |
| --- | --- |
| `恆常服務` | 按原分工表格式寫入自動生成的排班草稿 |
| `個案轉移紀錄_2025` | 原工作簿保留工作表 |
| `新同工跟服務紀錄表` | 原工作簿保留工作表 |
| `RC_變更摘要` | 本次上載檔案、目標週、變更與生成摘要 |
| `RC_審核` | 需要人工確認的項目，包含審核 ID、阻塞狀態、結構化理由、相關項目與來源證據 |
| `RC_未分配` | 未分配或未能安全落到原表格位的項目，包含原因代碼、審核 ID、來源與下一步 |
| `RC_meta` | 系統版本、模板來源、發放狀態、匯出前檢查與寫入統計 |

自動寫入或變更的主表儲存格會用批註和邊框標記，避免把原本的業務顏色語義直接覆蓋掉。
原有業務批註會保留；RosterCopiilot 只會追加一次自己的說明。需要覆核的格位批註會以 `RC:待審` 開始，並列出審核 ID。

## 發放狀態

系統會在生成時先做匯出前檢查：

| 狀態 | 意思 |
| --- | --- |
| `可發放` | 沒有硬性規則違反、未分配、需要審核項目或任何待處理 audit；可由具名人員執行獨立正式發佈 |
| `草稿需審核` | 沒有硬性規則違反，但仍有非阻塞審核項目需要確認 |
| `不可發放` | 仍有硬性規則違反、未分配項目或阻塞審核；只可作並行審核草稿 |

「下載審核草稿」永遠是並行審核材料。只有「可發放」版本經具名人員按下「發佈正式版」後，正式版下載才會出現；系統仍不會自動傳送或分發。

## 目前資料限制

- 樣本 HC 表是 2026 年 5 月資料。
- 樣本護送表是 2026 年 1 月資料。
- 系統只會採用目標週內的真實日期；如果目標週和某張上載表月份不匹配，該表會顯示 warning，不會自動補造需求。
- Demo 內置了部分同工技能 seed，讓排班器可以運作；正式版仍需要 NGO 提供同工技能、性別、可做路線、長者性別要求等 master data。
- 未確認資料不會被硬猜。涉及性別、技能、路線、專屬綁定等不確定項目會進入審核或資料缺口。
- 工程測試與 fixture parallel run 不等於 NGO 驗收。正式使用仍需要 NGO 確認 master data，並由 roster owner 完成及簽署兩個實際星期的並行比較。
